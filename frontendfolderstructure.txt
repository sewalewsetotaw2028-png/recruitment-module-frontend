Avoid too much nesting
There are many pain points associated with deep directory nesting in JavaScript projects. It becomes harder to write relative imports between them, or to update those imports when the files are moved. Unless you have a very compelling reason to use a deep folder structure, consider limiting yourself to a maximum of three or four nested folders within a single project. 
Naming Convention Guidelines
Files & Folders
PascalCase: React components, pages, layouts (EmployeeCard.tsx, DashboardLayout.tsx)
camelCase: hooks, services, utils (useEmployee.ts, apiClient.ts)
kebab-case: public assets (company-logo.png, add-user.svg)
snake_case / UPPER_SNAKE_CASE: constants & enums (ROLES_ADMIN, API_URL)
feature-specific types: employee.types.ts
Variables & Functions
camelCase for variables and functions (getEmployeeList, formatDate)
PascalCase for classes, components, and React context providers (EmployeeProvider)
Hooks
Must start with use prefix: useAuth, useDebounce, useEmployee
Redux
Slice files: camelCase (employeeSlice.ts)
Exported reducers: PascalCase (EmployeeReducer)
Utils / Lib
Export functions in camelCase
Keep feature-agnostic helpers in lib/
